# 完成の定義（Definition of Done）

> 完成の定義は、インクリメントがプロダクトに必要な品質基準を満たした状態を正式に記述したものである。
> プロダクトバックログアイテムが完成の定義を満たした瞬間にインクリメントが誕生する。
> — スクラムガイド 2020

## 対象プロダクト

InBusket（インバスケット学習Webアプリ） / 技術スタック想定: pnpm + Vite + React + TypeScript（ローカル稼働Webアプリ）

## 完成の定義

すべての項目が「はい」と判定できた場合に、そのプロダクトバックログアイテムは「完成」とみなす。

---

### 1. コード品質

| #   | 基準                                         | 判定          |
| --- | -------------------------------------------- | ------------- |
| 1-1 | TypeScript の型エラーがゼロである            | はい / いいえ |
| 1-2 | ESLint / Prettier でエラー・警告がゼロである | はい / いいえ |
| 1-3 | チーム内ペア確認（レビュー）が完了している   | はい / いいえ |

### 2. テスト

| #   | 基準                                                     | 判定          |
| --- | -------------------------------------------------------- | ------------- |
| 2-1 | 主要ロジック（出題・採点）に単体テストがあり全件成功する | はい / いいえ |
| 2-2 | 受入基準を満たす手動動作確認が完了している               | はい / いいえ |

### 3. ドキュメント

| #   | 基準                                                         | 判定          |
| --- | ------------------------------------------------------------ | ------------- |
| 3-1 | README に起動手順（pnpm install / pnpm dev）が記載されている | はい / いいえ |
| 3-2 | 案件データ（JSON）のスキーマと追加方法が説明されている       | はい / いいえ |

### 4. 動作確認

| #   | 基準                                              | 判定          |
| --- | ------------------------------------------------- | ------------- |
| 4-1 | ローカル環境（最新版 Chrome）でエラーなく動作する | はい / いいえ |
| 4-2 | 出題→回答→解説→次問のサイクルが破綻なく動作する   | はい / いいえ |

### 5. セキュリティ

| #   | 基準                                                                           | 判定          |
| --- | ------------------------------------------------------------------------------ | ------------- |
| 5-1 | `pnpm audit` で High/Critical の脆弱性が無い（または対応方針が記録されている） | はい / いいえ |
| 5-2 | シークレット情報がコードにハードコードされていない                             | はい / いいえ |

### 6. パフォーマンス

| #   | 基準                              | 判定          |
| --- | --------------------------------- | ------------- |
| 6-1 | 出題切替の応答が体感1秒以内である | はい / いいえ |

### 7. UI/UX の品質

| #   | 基準                                           | 判定          |
| --- | ---------------------------------------------- | ------------- |
| 7-1 | スマホ幅〜PC幅で表示崩れがない（レスポンシブ） | はい / いいえ |
| 7-2 | 主要操作（回答・次問）が1〜2タップで完結する   | はい / いいえ |

### 8. データベース

| #   | 基準                                                                           | 判定          |
| --- | ------------------------------------------------------------------------------ | ------------- |
| 8-1 | 案件データは JSON で管理され追加・修正が容易である（DBは本フェーズでは未使用） | はい / いいえ |

### 9. アクセシビリティ

| #   | 基準                                                             | 判定          |
| --- | ---------------------------------------------------------------- | ------------- |
| 9-1 | 主要操作（A/B/C 回答・次問・もう一度）がキーボードのみで完結する | はい / いいえ |
| 9-2 | フォーカス状態が視覚的に判別可能である（focus 可視）             | はい / いいえ |
| 9-3 | 操作可能要素に適切な role / aria 属性が付与されている            | はい / いいえ |

### 10. 入力検証・データ保護

| #    | 基準                                                                                                                                                     | 判定          |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| 10-1 | ユーザ入力（自由記述・数値・選択値等）に対し、最大長・型・必須/任意の妥当性検証が実装され、境界値の単体テストで検証されている                            | はい / いいえ |
| 10-2 | ユーザ入力をDOMへ反映する箇所で `dangerouslySetInnerHTML` / `innerHTML` を使用していない（Reactのテキスト描画またはエスケープ済みノードのみで出力する）  | はい / いいえ |
| 10-3 | セッション内/永続化（localStorage 等）で保持するデータは、読み込み時にスキーマ整合性（必須キー存在・型一致）を検証し、不整合時は安全にフォールバックする | はい / いいえ |

- 本DoDはチームの成熟度に応じて継続的に強化する。
