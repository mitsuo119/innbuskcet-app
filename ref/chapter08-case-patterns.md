---

## この章で学ぶこと

- インバスケットに頻出する20の案件パターン
- 各パターンの「模範解答の骨格」
- パターン認識で回答スピードを上げる方法

---

## パターンを知れば、試験は速くなる

インバスケットの案件は無限にバリエーションがあるように見えますが、実は**約20のパターンに分類**できます。パターンを知っていれば、案件を読んだ瞬間に「これは〇〇パターンだ」と認識でき、回答の骨格がすぐに浮かびます。

## 対外対応パターン（顧客・取引先）

### パターン 1: 顧客クレーム

**特徴**: 緊急度・重要度ともに高い。最優先案件。

```
[回答の骨格]
1. 顧客への初動対応（謝罪・受領連絡）を指示
2. 事実関係の調査を指示（担当者・期限）
3. 再発防止策の検討を指示
4. 必要に応じて上司・関係部署に報告
5. 顧客への正式回答の期限を設定

[キーフレーズ]
「まず本日中にお詫びと経過報告の連絡を行い…」
「事実確認の上、○日までに正式回答する方針で…」
```

### パターン 2: 取引先からの要求（値引き・仕様変更等）

**特徴**: 自分の一存では決められないことが多い。

```
[回答の骨格]
1. 要求の背景・意図を確認
2. 自社への影響を分析（コスト、他顧客への波及）
3. 受入可能な範囲を検討
4. 代替案があれば提示
5. 権限を超える場合は上司に提案の形で上申

[キーフレーズ]
「取引関係の維持と自社の収益のバランスを考慮し…」
```

### パターン 3: 新規取引・営業案件

**特徴**: 前向きだが、リスク評価が必要。

```
[回答の骨格]
1. ビジネス機会としての評価
2. リソース・リスクの確認
3. 関係部署（営業・法務等）との連携を指示
4. 判断の期限を設定
```

## 人事・部下マネジメントパターン

### パターン 4: 部下の退職・異動の相談

**特徴**: ヒューマンスキルが最も問われる案件。

```
[回答の骨格]
1. まず直接面談の場を設ける（メールではなく対面）
2. 本人の話をしっかり聴く姿勢を示す
3. 退職理由・不満の本質を探る
4. 組織として対応できることを検討
5. 最終的には本人の意思を尊重する姿勢

[キーフレーズ]
「まず本人と直接面談する時間を設け、
 じっくり話を聴いた上で…」
「本人の気持ちを十分に理解した上で、
 組織として対応できることを検討します」
```

### パターン 5: 部下間の対立・人間関係トラブル

**特徴**: 事実確認が最重要。片方の言い分だけで判断しない。

```
[回答の骨格]
1. 双方から個別に事情を聴く
2. 事実と感情を分けて整理
3. 公平な立場で調整する方針を示す
4. 必要に応じてチーム体制の見直しを検討
```

### パターン 6: 部下のパフォーマンス問題

**特徴**: 叱責ではなく、改善支援の姿勢が重要。

```
[回答の骨格]
1. 具体的な事実に基づいて状況を把握
2. 本人と面談し、原因を把握（スキル不足？モチベーション？家庭の事情？）
3. 具体的な改善目標と支援策を提示
4. 定期的なフォローアップの仕組みを作る
```

### パターン 7: 部下の有給・休暇申請

**特徴**: 通常はC案件。業務に支障がなければ承認。

```
[回答の骨格]
1. 業務への影響を確認
2. 代替要員の確保を指示
3. 承認

[注意] 簡潔でOK。1〜2行で十分。
```

### パターン 8: ハラスメント報告

**特徴**: コンプライアンス案件。自動的にA案件。

```
[回答の骨格]
1. 報告者の安全を最優先で確保
2. 事実関係を慎重に調査（人事部と連携）
3. 法令に基づいた対応を行う
4. 守秘義務を厳守する旨を関係者に伝達
5. 上位者に報告

[絶対にやってはいけないこと]
・報告者を責める
・当事者同士で話し合わせる
・他の人に漏らす
```

## 業務・プロジェクトパターン

### パターン 9: プロジェクト遅延・品質問題

**特徴**: エンジニアが最も経験のあるパターン。

```
[回答の骨格]
1. 遅延・品質問題の影響範囲を把握
2. 原因を分析（要因の切り分け）
3. リカバリー策を指示（増員？スコープ変更？期限延長？）
4. ステークホルダーへの報告
5. 再発防止策を検討

[エンジニアの強みが活きるポイント]
技術的な問題の構造化が得意なはず。
「原因を切り分ける」プロセスを明示すると高評価。
```

### パターン 10: 予算承認・経費申請

**特徴**: 金額と権限の範囲を確認する。

```
[回答の骨格]
1. 費用対効果を確認
2. 予算の範囲内か確認
3. 承認/条件付き承認/上申のいずれかを判断
4. 理由を明記
```

### パターン 11: 業務改善提案

**特徴**: 部下からのボトムアップ提案。前向きに受け止める。

```
[回答の骨格]
1. 提案に対する感謝・評価
2. 実現可能性と効果の検討を指示
3. 次のステップ（試行導入、関係者への説明等）
4. 提案者を推進役にする（部下の成長機会）
```

### パターン 12: 会議・セミナーへの参加依頼

**特徴**: 通常はC案件。

```
[回答の骨格]
1. 参加のメリットを判断
2. 業務との兼ね合いを確認
3. 参加/不参加/部下に参加させる のいずれかを判断

[ヒント] 重要な会議なら自ら出席、情報収集目的なら部下に委任。
```

## リスク・トラブルパターン

### パターン 13: 事故・災害報告

**特徴**: 最優先。人命と安全が第一。

```
[回答の骨格]
1. 人的被害の確認と安全確保（最優先）
2. 被害の拡大防止措置
3. 関係先への報告（上司、関係部署、必要に応じて行政機関）
4. 原因調査と再発防止策
```

### パターン 14: 情報セキュリティインシデント

**特徴**: エンジニアの知識が活きるパターン。

```
[回答の骨格]
1. 被害範囲の特定と封じ込め
2. 関係者（情報セキュリティ部門、法務、経営層）への報告
3. 顧客情報が含まれる場合の対外対応
4. 原因調査と再発防止策
```

### パターン 15: コンプライアンス違反（不正行為）

**特徴**: 自動的にA案件。適切な対応が強く求められる。

```
[回答の骨格]
1. 事実関係の慎重な確認
2. コンプライアンス部門・法務部門への相談
3. 上位者への報告
4. 証拠の保全
5. 関係者への守秘義務の徹底
```

## 組織・方針パターン

### パターン 16: 組織変更・人員配置

**特徴**: 多くの関係者に影響する。

```
[回答の骨格]
1. 変更の目的・背景を確認
2. 影響を受ける関係者を特定
3. 上位者の方針との整合性を確認
4. 段階的な実施計画を立てる
5. 関係者への丁寧な説明を計画
```

### パターン 17: 上位方針の伝達・対応

**特徴**: 上から降りてきた方針を部署に展開する。

```
[回答の骨格]
1. 方針の内容を正確に理解
2. 自部署への影響を分析
3. 具体的なアクションプランを策定
4. 部下への説明と納得感の醸成
```

### パターン 18: 他部署からの依頼・調整

**特徴**: 協力姿勢を見せつつ、自部署の負荷も考慮。

```
[回答の骨格]
1. 依頼内容の確認
2. 自部署のリソース状況を確認
3. 協力の方向性を示す（全面協力/部分協力/条件付き）
4. 具体的な対応範囲と期限を合意
```

## その他のパターン

### パターン 19: 前任者の未完了案件

**特徴**: インバスケット特有の設定。前任者の方針を引き継ぐ。

```
[回答の骨格]
1. 前任者の方針・経緯を確認
2. 継続すべきか見直すべきかを判断
3. 関係者に着任の挨拶と方針を伝達
```

### パターン 20: 複合案件（複数パターンの組み合わせ）

**特徴**: 高難度。A案件になりやすい。

```
[対応のポイント]
1. 案件を要素に分解する
2. 優先順位の高い要素から対応する
3. 関連する他の案件と紐づけて対応する
```

## パターン認識の練習方法

1. **過去問や模擬問題を解いたあと**、各案件がどのパターンに該当するかを分類する
2. **各パターンの骨格を暗記**する（20パターン×骨格5行＝100行程度）
3. 本番では、案件を読んだ瞬間に「これはパターン○だ」と認識する

パターンを認識できれば、回答の骨格が即座に浮かび、あとは**案件固有の情報を当てはめるだけ**になります。回答スピードが劇的に上がります。

:::message
**この章のまとめ**: インバスケットの案件は約20パターンに分類できる。各パターンの回答骨格を事前に身につけておけば、本番で迷う時間が大幅に減り、すべての案件に対応する余裕が生まれる。パターン認識力＝時間短縮＝合格への近道です。
:::
