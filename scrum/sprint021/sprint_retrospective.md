## Keep / Problem / Try（5観点・確定）

### Keep（維持）

- **個人（田中）**: DAY1 に TASK-081-1（`src/routes.ts` 単一ソース新設＋`Router.tsx` の `VALID_REFERENCE_IDS` 導出化）を最優先で完了し、PBI-077（href 棚卸し）/PBI-078（メタマトリクス棚卸し）の前提を午前で確立。3 PBI 並走の起点を堅牢化した。
- **個人（伊藤）**: TASK-077-1 の onClick 単独遷移網羅監査を DAY1 で完了し、Router.tsx の delegated click と nav.ts 公開関数のみへの集約方針を提示。後続 TASK-077-2/3 の方向性を即時固定でき、属人的判断を排除した。
- **相互作用**: 山本（TASK-077-2）／中村（TASK-081-4・078-5）の助っ人作業が DAY3〜4 に集中投下され、コア（伊藤・田中）の TASK-077-3/4・TASK-078-2/3/4 と完全並走。`handoff_for_helpers.md` の事前読み込み（A-96）が Day1 立ち上がり時間短縮に直結した。
- **プロセス**: A-95（Sprint Review §公開後確認テンプレ）/ A-96（助っ人事前メモ DAY3 着手・DAY4 完成）/ A-93（2 区分受入確認メモ）の3 Try が同一スプリント内で同時定着し、相互補完で運用負荷を増やさず標準運用化できた。
- **ツール**: `src/routes.ts` 単一ソース化が 3 PBI（sitemap 生成・href 化対象棚卸し・メタマトリクス棚卸し）の共通基盤として機能し、CI（`sitemap-coverage.test` / `Router.seo.test.tsx` / `Router.history.test.tsx`）でルート追加→各種整合の自動追従が確立。今後コンテンツ系 PBI（PBI-079/080）でルート追加するだけで sitemap/canonical/メタ重複/href 整合が自動担保される設計が成立。
- **完成の定義**: DoD 21 項目すべて「はい」を全 PBI で達成。`pr_checklist.md` §10（SEO / サイトマップ整合）の三角リンク（seo_operations ↔ lighthouse-sprint016 ↔ pr_checklist §10）が PBI-081 自動生成手順反映で更に補強された。

### Problem（課題）

- **プロセス**: 公開後確認 C1'〜C4'（PBI-081/077/078 本番反映後の最終裏取り）と K-1（order011(b) Search Console KPI 取得運用）が Sprint Review 直後・Sprint022 DAY5 と複数タイミングに分散。Sprint020 から導入した A-95 標準フォーマットは機能しているものの、**「測定 0 期（公開後 14 日未満）」など PBI 横断の前提条件を明示する欄**が現フォーマットに不在。
- **プロセス**: 助っ人事前メモ（A-96）は DAY3 着手・DAY4 完成で安定したが、**Sprint022 候補 PBI が 5pt × 2件（PBI-079/080）と粒度が大きく、両投入か単独投入＋小粒併走かの判断が DAY5 まで残った**。プランニング前判断材料の事前整理（容量判定）の標準化余地あり。
- **完成の定義**: 現行 DoD で品質判定は一貫しており、Sprint021 での問題は見当たらない（変更不要）。

### Try（試行）

- **プロセス（最優先）**: A-95 標準フォーマットに **「測定前提条件欄」**（公開後 N 日未満／クロール待ち／本番計測値未取得 等の前提を PBI 横断で明示）を追加し、Sprint022 から運用開始する。これにより Sprint Review §8 で「受入の前提に含めない」根拠が前提条件欄を参照する形で恒常化される。
