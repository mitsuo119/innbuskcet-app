# 依頼事項メモ order017

## 依頼者

顧客: 佐藤（上長不在のため代行作成）

## 依頼概要（最重要）

本番サイト https://inbasket-app.com/ を GitHub Pages カスタムドメインで公開後、顧客側で実機レビューを行ったところ、**致命的なルーティング不具合**を発見した。Sprint026 のコンテンツ修正（プリレンダ本文の焼き込み・クローキング解消）は静的HTMLレベルでは成功しているが、**JS実行後にトップ以外の全ページが「ページが見つかりません(404)」コンポーネントに化けている**。

このままでは Googlebot から見て有効なコンテンツページがトップしか存在しないことになり、AdSense再申請をしても前回と同じ「有用性の低いコンテンツ」で確実に落ちる。**再申請の前にこれを根治することが最優先**。

---

## 不具合の事実（実機実測済み）

### 事象

- サーバが返す**静的HTML（プリレンダ）は良好**。
  - 例: `/reference/chapter01/` は本文約 1,938 字が `hidden` 等の隠し属性なしで可視で出力されている。view-source で確認済み。
- しかし **JavaScript hydration 完了後**、トップ `/` 以外の以下すべてのURLが NotFound コンポーネント（"ページが見つかりません"）に置き換わる：
  - `/about` / `/privacy-policy` / `/reference` / `/reference/chapter01`〜`chapter12` / `/cases` / `/cases/<id>` / `/patterns` / `/patterns/<id>` 等
- 結果として、せっかくプリレンダで焼き込んだ良質な本文を、クライアント側ルータが 404 で上書きしている。

### 原因（コード調査済み）

- GitHub Pages のカスタムドメインは、ディレクトリ型URLへのアクセスを**末尾スラッシュ付き**にリダイレクトする（例: `/about` → `/about/`）。
- 一方、クライアントルータ [project/front/src/Router.tsx](../../project/front/src/Router.tsx) の `parsePathname()` は**末尾スラッシュなし前提で完全一致判定**している。
- このため、本番で実際にブラウザに渡るパス（末尾スラッシュ付き）がどのルート定義にもマッチせず、全件 NotFound にフォールバックしている。

### 影響

- Googlebot（JS描画あり）から見ると、トップ以外に有効なコンテンツページが**ゼロ**。
- AdSense / Search の評価上、サイトが「事実上1ページしかない」状態と判定される。
- Sprint024〜026 の SEO / プリレンダ / コンテンツ強化の成果がすべて無効化されている。

## 顧客としての要望（優先度順）

### P0（再申請前に必須・最優先）

1. **ルーティングの末尾スラッシュ非対応バグを根治する**
   - [Router.tsx](../../project/front/src/Router.tsx) の `parsePathname()` 等のパス解決ロジックを、末尾スラッシュ有無の両方を等価に扱うように修正する。
   - 修正方針は実装者に委ねるが、「正規化（末尾スラッシュ除去後にマッチング）」が最もシンプルと考えられる。
   - 影響範囲: 全ページ（一覧ページ含む）。

2. **本番（または本番同等）での実機検証**
   - 修正後、本番ドメイン（または GitHub Pages の preview / 同等構成）で、**JS hydration 完了後も**以下が正しく表示されることを目視＋自動で確認する：
     - `/about/` / `/privacy-policy/` / `/reference/` / `/reference/chapter01/`〜`chapter12/` / `/cases/` / `/cases/<id>/` / `/patterns/` / `/patterns/<id>/`
   - 検査観点: 「NotFound コンポーネントが表示されていないこと」「本文が正しく描画されていること」。

3. **再発防止のテスト追加**
   - 末尾スラッシュ付きURL（`/about/`, `/reference/chapter01/` 等の代表ケース）でルータが正しいページコンポーネントに解決することをユニットテストで担保する。
   - 末尾スラッシュなしと末尾スラッシュ付きの両方で同じページに解決することをテストで明示する。

### P1（P0完了後すぐ）

4. **AdSense再申請の実施**
   - 上記 P0 がすべて完了し、本番で全ページが正しく表示されることが確認できたら、AdSense 再申請に進む。
   - 再申請前のチェックリスト（[project/docs/adsense_resubmission_checklist.md](../../project/docs/adsense_resubmission_checklist.md)）に**「本番JS実行後にトップ以外の代表ページが404化していないこと」**を追加してほしい。

## 顧客の温度感

- コンテンツ自体は Sprint026 で本当に良くなった。view-source レベルでも各章で 1,000〜2,000 字の本文が可視で出ている。これは前進。
- ただし、**ルーティングのバグ1つで全滅していた**のは率直に残念。
- 一方で、**公開前ではなく公開直後でも実機で気づけた**のは大きな前進。今後は「ローカルで動く」「ビルドが通る」「静的HTMLが良い」だけで完了とせず、**実際にGoogle（=JS実行後のブラウザ）から見えている状態**まで検証してから完了としてほしい。
- これは Sprint026 のレトロで挙がっていた「アウトカム検証(A-120)」そのものなので、今回の対応をきっかけに DoD §4-3 への組み込みも前進させてほしい。
