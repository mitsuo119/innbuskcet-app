## トピック1: Why（スプリントゴール）

### ゴール策定の議論

**高橋（SM）**: order007（Sprint014 向け追加依頼）で起票された PBI-061〜064 が Ready 化済みです。Sprint013 レトロの A-74/A-75/A-76 もスプリント運用の中で回収していきます。今回は「解説リファレンスの表示品質を一般ユーザ視点に揃える」ことと「主要画面の UX を局所化された CSS 分割方針で改善する」ことを束ねたゴールにしたいです。

**鈴木（PO）**: 主軸は PBI-061 / 062 / 063 の 7pt です。PBI-061 の見出し自然言語化を先に確定させ、PBI-062 の回遊導線と整合させる順番が安全です。PBI-063 は問題回答系画面群の視認性とモバイル操作性が中心で、ユーザ価値が高い。PBI-064 は余力時のストレッチで十分です。

**伊藤（Dev）**: PBI-061 は変更点が局所的なので Day1 で確定できます。PBI-062 は PBI-060 で確立した CSS 分割（画面単位）方針に沿って `ReferencePage.css` を中心に閉じ込められます。

**田中（Dev）**: PBI-063 は対象画面が複数あるので、3 画面に範囲を区切って Day3〜4 に集中させたいです。A-75（CSS 分割横展開ルール）の `pr_checklist.md` 追記は PBI-062 着手前の Day2 までに済ませて、PBI-063 でも同じ規律を使えるようにします。

### スプリントゴール（確定）

> **「解説リファレンス表示の不要な内部表記を排除して章間回遊を整え、問題回答系の主要画面を CSS 分割方針に沿って視認性・モバイル操作性の面で底上げする」**

- PBI-061 で表示文言を一般ユーザ視点へ整え、PBI-062 で解説エリアの UX を仕上げる
- PBI-063 で問題回答系の主要 3 画面以上を底上げし、ストレッチで PBI-064 のナビ一貫性まで広げる余地を残す
- 全員合意: 鈴木 ✓ / 伊藤 ✓ / 田中 ✓
