## 依頼概要

Sprint004 で「同僚共有に耐える完成度」（テーマ切替・履歴件数選択・モード別正答率・履歴コントラスト）が達成され、社内勉強会のデモに耐える水準まで到達した。
しかし**昇進試験合格直結**という観点では、依然として「優先度選択クイズ」の枠を出ていない。
Sprint005 では、ユーザ（上長）の強い要望である **「インバスケット昇進試験に合格するための機能」の本丸**、すなわち
**記述機能（PBI-023 判断・理由・アクション ／ PBI-024 模範比較）と時間制限モード（PBI-027）** に踏み込む。

## 背景・目的

- Sprint004 レビューで佐藤フィードバック1 として「PBI-023/024 を Sprint005 で**最優先**にしてほしい」と明言済み。`product_backlog.csv` で PBI-023/024 は既に **Critical** に昇格済。
- `ref/chapter09` の「① 判断 → ② 理由 → ③ アクション」の 3 ブロック型は、本番試験で**記述必須**。これを反復できなければ合格答案の型が身につかない。
- `ref/chapter12` の「20 問 90 分」のタイムマネジメントは、当日の最大の落とし穴。本番再現モード（PBI-027）は**合格直結**。
- Sprint004 レトロ T-6 / A-17 で、記述機能着手に合わせて DoD §10「入力検証・データ保護」（10-1 入力検証 / 10-2 XSS 防止 / 10-3 保存データスキーマ整合）を新設する方針を合意済み。
- 一方、Sprint004 は計画 6pt（A-13 下限割れ）で着地。Sprint005 は新領域（記述評価・cases.json スキーマ拡張）と DoD §10 試行が重なるため、A-18 で **6〜9pt** が指針。**詰め込みは禁物**。

## Sprint005 で達成したいこと（佐藤の優先方針）

### 最優先：「合格答案の型」を身につける（記述機能）

`ref/chapter09`「① 判断 → ② 理由 → ③ アクション」の反復が**昇進試験合格の中核**。Sprint005 は何よりここに踏み込む。

1. **PBI-023（3pt / Critical）**: 案件画面で 3 ブロックを自由記述できる。プレビュー表示とセッション内保持。
   - **絶対に外せない**。これがないと記述練習自体ができない。
2. **PBI-024（3pt / Critical）**: 模範回答骨格と採点ポイント（5W1H/委任/フォロー/関連）を並列表示。
   - PBI-023 と同時に入って初めて「合格答案との差分から学ぶ」が成立する。**できればセット投入**を希望。

### 次点：本番再現でタイムマネジメントを体に覚える

3. **PBI-027（3pt / Medium）**: 20 問 90 分の連続演習。残り時間警告・自動終了。
   - chapter12 の本丸。Sprint005 で容量に収まれば投入、収まらなければ **Sprint006 最優先**で必ず取る。

### 段階導入候補（容量があれば）

## 非機能・制約

- 技術構成は pnpm + Vite + React + TypeScript を維持
- ローカルブラウザ単独で完結（認証・DB・APIは引き続きスコープ外）
- 自由記述（PBI-023）は**セッション内のみ保持**で確定（order004 確認事項1で合意済 → localStorage 保存はスコープ外）
- cases.json 拡張（PBI-024）は **既存構造に追加フィールドとして格納**（order004 確認事項2で確定）。既存 40 件はオプショナル扱いで段階移行可能
- 6 軸自己採点（PBI-025）は**回答後都度入力**で確定（order004 確認事項3）
- 時間制限モード（PBI-027）は **20 問固定 / 90 分固定**で確定（order004 確認事項4）
- 助っ人（山本・中村）は引き続き handoff 運用。A-16 で還流欄構造化を試行
