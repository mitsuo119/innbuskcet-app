## 意思決定力 ＝ インバスケットの最重要スキル

第2章で述べたとおり、**意思決定力は最も配点が高い**ディメンションです。

インバスケットの案件は、意図的に**判断しにくい状況**が設定されています。

- 情報が不足している
- どちらの選択肢にもメリット・デメリットがある
- 関係者の利害が対立している
- 時間的な制約がある

それでも「判断を示す」ことが求められます。

## 意思決定の5ステップ

すべての案件で、以下の5ステップを3分以内に回せるようになりましょう。

```
Step 1: 問題を特定する
  「この案件の本質的な問題は何か？」

Step 2: 選択肢を挙げる
  「取りうる対応は何があるか？」

Step 3: 判断基準を定める
  「何を基準に判断するか？」

Step 4: 決定する
  「どの選択肢を採用するか？」

Step 5: 理由と指示を書く
  「なぜその判断をしたか？誰に何を指示するか？」
```

### 実践例

**案件**: 重要顧客の山田商事から「御社の製品に不具合がある。今週中に回答がなければ取引を見直す」というメール。

```
Step 1: 問題の特定
  → 重要顧客からの製品不具合クレーム。取引継続のリスクあり。

Step 2: 選択肢
  A: 事実確認を待ってから回答する
  B: まず謝罪と受領連絡を行い、並行して調査する
  C: 営業部に丸投げする

Step 3: 判断基準
  → 顧客との信頼関係維持（経営方針）+ スピード

Step 4: 決定
  → B を採用する

Step 5: 回答
  「本日中に山田商事に受領と経過報告の連絡を行う。
   品質管理部の鈴木主任に不具合内容の調査を依頼し、
   明日17時までに報告をもらう。調査結果を踏まえ、
   木曜日に山田商事へ正式回答する方針。
   営業部の佐藤課長にも情報共有し、顧客との関係維持に
   配慮した対応とする」
```

## 判断の「型」テンプレート

毎回ゼロから考えるのは時間がかかるので、事前に「型」を持っておきます。

### 型 1: 承認型

```
「承認します。
 理由：[判断根拠]。
 ただし、[条件/留意事項]については[担当者]に確認してください。
 結果を[期限]までに報告してください」
```

**使うケース**: 予算承認、企画承認、出張申請、有給申請など

### 型 2: 対応指示型

```
「[対応方針]で進めてください。
 理由：[判断根拠]。
 具体的には：
 1. [担当者A]が[アクション1]を[期限]までに実施
 2. [担当者B]が[アクション2]を[期限]までに実施
 関連部署の[部署名]にも情報共有してください。
 進捗は[タイミング]で私に報告してください」
```

**使うケース**: 顧客対応、トラブル対応、プロジェクト進行

### 型 3: 方針決定型

```
「[選択肢A]ではなく[選択肢B]で進める方針とします。
 理由：[判断根拠]。
 [選択肢A]のリスクは[リスク内容]であり、
 [選択肢B]のほうが[メリット]が大きいと判断しました。
 [担当者]に方針を伝え、[次のアクション]を指示してください」
```

**使うケース**: 二択・三択で判断を迫られる案件

### 型 4: エスカレーション型

```
「本件は[理由]のため、[上位者]に報告・相談の上で対応します。
 ただし、[緊急対応]は先行して実施してください。
 [担当者]に[暫定対応の指示]を出してください」
```

**使うケース**: 自分の権限を超える案件（大規模な予算、人事異動、法的問題）

### 型 5: 情報収集型

```
「現時点では情報が不足しているため、[暫定方針]で進めつつ、
 [担当者]に[確認すべき事項]を[期限]までに調査してもらいます。
 調査結果を踏まえ、最終的な判断を[いつ]までに行います。
 なお、調査結果によっては[代替方針]に変更する可能性があります」
```

**使うケース**: 判断に必要な情報が不足している案件

:::message alert
**重要**: 「情報収集型」は便利ですが、多用は厳禁です。全案件の過半数をこの型で処理すると「判断を先送りしている」とみなされ、意思決定力が低評価になります。**全体の2割以下**にとどめましょう。
:::

## 判断を先送りしてよいケース/いけないケース

### 先送りしてよい（情報収集型を使ってよい）

- 法的な問題が絡み、専門家の見解が必要
- 金額が非常に大きく、上位者の承認が不可欠
- 事実関係が不明で、判断を誤ると被害が拡大する

**ただし、必ず暫定対応と調査指示をセットで書くこと。**

### 先送りしてはいけない

- すでに十分な情報が案件文に書かれている
- 顧客やステークホルダーが回答を待っている
- 他の案件と関連しており、この判断が前提になっている

## 判断に迷ったときの最終手段

どうしても判断がつかない場合、以下の優先順位で判断してください。

```
1. 顧客（外部）の利益を守る判断
2. 会社（組織）の利益を守る判断
3. 部下（チーム）の利益を守る判断
4. 自分の利益を守る判断（最下位）
```

これは多くの企業が掲げる「顧客第一」の方針と一致するため、まず外れることはありません。

**エンジニア向けの例え**: 本番障害が発生したとき、「ユーザーへの影響を最小化する > サービスの信頼性を守る > チームの負荷を考慮する」の順で判断しますよね。同じ感覚です。

:::message
**この章のまとめ**: 意思決定は5ステップで回す。判断の「型」を5つ持っておく。情報不足でも暫定方針を示す。迷ったら顧客→会社→部下→自分の順で判断する。型を身体に染み込ませれば、3分以内で自信を持って判断を書けるようになります。
:::
