# プルリクエスト チェックリスト

> Sprint004 / TASK-011（A-11）成果物。InBusket フロントエンド開発における PR 作成時の標準チェックリスト。
> Sprint レトロスペクティブで運用化を判断する試行版。

## 対象範囲

`project/front/` 配下の変更を伴うプルリクエスト全般。

---

## 0. 前提

- [ ] 作業ブランチを最新の `main` から派生・リベース済
- [ ] PR タイトル / 本文に対象 PBI ID（`PBI-XXX`）または TASK ID（`TASK-XXX`）を含めた
- [ ] Issue に `sprint/*` または `test/*` ラベルが付いている場合、PR にも同じラベルを付与した（`.github/copilot-instructions.md`）
- [ ] PR 本文に `Fixes #<issue番号>` を記載した（該当する場合）

## 1. コード品質（DoD §1）

- [ ] `pnpm lint` がエラー・警告ゼロで完了する
- [ ] `pnpm build`（= `tsc -b && vite build`）が型エラーゼロで完了する
- [ ] チーム内ペア確認（伊藤 / 田中 / 山本 / 中村のいずれか）でレビュー済

## 2. テスト（DoD §2）

- [ ] `pnpm test` が全件 PASS する（既存テストの破壊を含まない）
- [ ] 追加・変更したロジックに対応する単体テストを追加した
- [ ] 受入基準に基づく手動動作確認をローカル（最新 Chrome）で完了した

## 3. ドキュメント（DoD §3）

- [ ] README / docs に必要な変更を反映した（起動手順・データ追加手順に影響する変更時）
- [ ] 案件データ（`src/data/cases.json`）のスキーマ変更時はドキュメントも更新した

## 4. 動作確認（DoD §4 / §6）

- [ ] 出題 → 回答 → 解説 → 次問のサイクルが破綻なく動作する
- [ ] 出題切替の応答が体感 1 秒以内である

## 5. セキュリティ（DoD §5）

- [ ] シークレット情報（API キー、トークン、パスワード等）をコードにハードコードしていない
- [ ] 新規 npm 依存を追加した場合、`pnpm audit` で High / Critical 脆弱性がないことを確認した
- [ ] メジャーバージョン更新を行う場合、PO（鈴木）の事前合意を得た（A-7 ルール）

## 6. UI / UX（DoD §7）

- [ ] スマホ幅（〜480px）〜 PC 幅で表示崩れがないことを確認した
- [ ] 主要操作（回答・次問）が 1〜2 タップ／キー入力で完結する

## 7. アクセシビリティ（DoD §9 / `project/docs/a11y_checklist.md`）

- [ ] §9-1 主要操作（A/B/C 回答・次問・もう一度・モード切替・テーマ切替）がキーボードのみで完結する
- [ ] §9-2 フォーカス状態が視覚的に判別可能（`:focus-visible` 等）
- [ ] §9-3 操作可能要素に適切な `role` / `aria-*` が付与されている
- [ ] 色のみで意味を伝えていない（記号・テキスト併記）
- [ ] ライト / ダーク両テーマで WCAG 2.1 AA コントラスト比 4.5:1 以上を満たす（テーマ関連変更時）

## 8. 案件データ追加（A-11 / `project/docs/case_pattern_mapping.md`）

> 案件データ（`cases.json`）追加・改廃を伴う PR のみ対象。

- [ ] 追加後、A / B / C の各優先度が **30% 以上** の比率を保つ（採点学習体験のバランス維持）
- [ ] `case_pattern_mapping.md` の章節マッピング（ref/chapter08-case-patterns.md）を更新した
- [ ] 受入基準として「優先度判定」と「解説本文」が一次資料（ref/）に基づくことを記録した

## 9. 入力検証・データ保護（DoD §10 / Sprint005 で初適用）

> ユーザ入力（自由記述・数値・選択値）または永続化データを扱う PR のみ対象。

- [ ] §10-1: 入力に対し最大長 / 型 / 必須・任意 の妥当性検証を実装し、境界値の単体テストで検証した
- [ ] §10-2: ユーザ入力を DOM に反映する箇所で `dangerouslySetInnerHTML` / `innerHTML` を使用していない（React テキスト描画のみ）
- [ ] §10-3: セッション内 / 永続化データの読み込み時にスキーマ整合性（必須キー存在・型一致）を検証し、不整合時は安全にフォールバックする

## 10. コミット / PR 体裁

- [ ] コミットメッセージは Conventional Commits 風（`feat(front): ...`, `fix(front): ...` 等）
- [ ] PR タイトルに変更概要を簡潔に記載
- [ ] 大きな変更（>500 行）は分割を検討した
