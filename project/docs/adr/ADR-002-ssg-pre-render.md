## コンテキスト

order014 で AdSense「有用性の低いコンテンツ」審査落ちへの対応として、最有力仮説「SPA クローラ可視性不足」を解消する必要がある。本アプリは現状 React + Vite SPA で、初期 HTML には `<div id="root"></div>` と `<noscript>` フォールバックのみが含まれ、本文・h1・主要メタはクライアント側 JS 実行後に注入される。Googlebot は JS レンダリングに対応するが、AdSense クローラ（Mediapartners-Google）の JS 対応は限定的で、`view-source:` 段階で本文テキストが取得できない構造が審査落ちの主因である可能性が高い。

本 ADR では「SSG/Pre-render の採否」を **6 軸評価で 4 候補から 1 案を確定**し、PoC 実装方針を決める。

## 検討した選択肢

| 選択肢ID | 選択肢                             | 概要                                                                                                                                          |
| -------- | ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| C1       | vite-plugin-prerender 系           | ビルド時に Puppeteer/Playwright で各ルートを静的 HTML 化。SPA 挙動は実行時に hydrate で維持。                                                 |
| C2       | 自前静的 HTML 生成スクリプト       | `scripts/prerender.mjs` で `routes.ts` から URL 列挙→ `vite preview` または node-html-parser で各ルート HTML を生成。最小実装で依存追加なし。 |
| C3       | SSR 全面移行（Next.js / Remix 等） | Vite + React SPA を SSR フレームワークに置換。本文サーバ生成。                                                                                |
| C4       | 現状維持 + `<noscript>` 強化       | 既存 `index.html` の `<noscript>` に主要本文を 200 字以上展開。SSG/Pre-render は導入せず。                                                    |

## 評価軸（6 軸 × 1〜5 点 / 高いほど良い）

| 評価軸                                 | 観点                                                                                                                                   |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| E1. クローラ可視性（AdSense + Google） | `view-source:` で本文・h1・メタが取得できるか。AdSense クローラ JS 非対応前提で評価。                                                  |
| E2. 既存 SPA 挙動維持                  | クライアントルーティング・状態保持・既存 vitest 全 PASS が維持できるか。                                                               |
| E3. ビルド時間                         | `pnpm build` 所要時間の増加幅（現状 ~10s 想定）。                                                                                      |
| E4. 保守コスト                         | 追加依存・追加スクリプト・追加 CI ステップの保守負荷。新規メンバーの学習コスト。                                                       |
| E5. バンドル影響                       | dist サイズ・hydrate 時の二重評価・初期表示速度への影響。                                                                              |
| E6. テスト退行リスク                   | 既存 vitest 579+ ／ `Router.seo.test.tsx` 13 ／ `seo-assets.test.ts` 33 への退行影響。AdSense ローダー Vite プラグイン衝突リスク含む。 |

### DAY1 ドラフト所見

- **C2（自前静的 HTML 生成スクリプト）が C1 より +4 点**: 既存 `scripts/copy-404.mjs` の延長で薄く実装でき、AdSense ローダー Vite プラグイン（PBI-050/052）との衝突を最小化できる。`routes.ts` 単一ソース基盤（PBI-081）と相性が良い。
- **C4（現状維持+noscript 強化）が表上は最高得点 27**: ただし E1=2 でクローラ可視性が AdSense 観点で最弱。order014 主目的「AdSense 再申請」の達成見込みが本質的に低く、**E1 の重み付けを 2 倍する**重み付き評価を DAY2 で再実施し、最終採用案を決定する想定。
- **C3（SSR 全面移行）**: E1 は最高だが E2/E4/E6 が最低で、本スプリント PoC のスコープ（2 ルート）を超えるため除外候補。
- **C1（vite-plugin-prerender）**: 候補としては成立するが、Puppeteer/Playwright 追加で E3/E4 が下がる。C2 で同等成果が得られる場合は採用しない。

### DAY2 で実施する重み付き再評価（暫定提案）

- **重み**: E1=×2、E2〜E6=×1（AdSense 再申請が最優先のため E1 を重視）
- **重み付き合計（暫定）**:
  - C1: 5×2 + 4 + 3 + 3 + 3 + 3 = **26**
  - C2: 5×2 + 4 + 4 + 4 + 4 + 4 = **30**
  - C3: 5×2 + 2 + 3 + 1 + 3 + 1 = **20**
  - C4: 2×2 + 5 + 5 + 5 + 5 + 5 = **29**
- **暫定 1 位**: C2（自前静的 HTML 生成スクリプト）。C4 と僅差のため DAY2 で渡辺セキュリティ事前合意を取りつつ最終確定。

## 決定

**C2: 自前静的 HTML 生成スクリプト** を採用する（DAY2 重み付き再評価で 30 点で 1 位）。

### DAY2 確定採点（重み: E1=×2、E2〜E6=×1）

| 評価軸                  | C1 vite-plugin-prerender | C2 自前静的 HTML 生成 | C3 SSR 全面移行 | C4 現状維持+noscript |
| ----------------------- | ------------------------ | --------------------- | --------------- | -------------------- |
| E1 クローラ可視性（×2） | 5 → 10                   | 5 → 10                | 5 → 10          | 2 → 4                |
| E2 SPA 挙動維持         | 4                        | 4                     | 2               | 5                    |
| E3 ビルド時間           | 3                        | 4                     | 3               | 5                    |
| E4 保守コスト           | 3                        | 4                     | 1               | 5                    |
| E5 バンドル影響         | 3                        | 4                     | 3               | 5                    |
| E6 テスト退行           | 3                        | 4                     | 1               | 5                    |
| **重み付き合計**        | **26**                   | **30（採用）**        | **20**          | **29**               |

### 決定根拠（暫定 → 確定の差分理由）

- **C2 が C4 を 1 点上回った決定打**: AdSense 再申請の主目的（E1）に最大重みを付与した結果、C4 の「クローラ可視性 2/5」が再申請成功確率を有意に下げる構造的弱点と評価。
- **C2 が C1 を 4 点上回った理由**: 既存 `scripts/copy-404.mjs`（PBI-076）の延長で薄く実装でき、Puppeteer/Playwright 等の重量級依存追加を回避できる（E3/E4/E6 で +1 ずつ）。`routes.ts` 単一ソース基盤（PBI-081）と相性が良い。
- **C3 を除外した理由**: SSR 全面移行は本スプリント PoC スコープ（2 ルート）を大幅に超過し、E2/E4/E6 が最低で既存 vitest 579+ への退行リスクが過大。
- **AdSense ローダー Vite プラグイン（PBI-050/052）との両立**: C2 はビルド成果物（dist/index.html 等）に対する後処理として静的 HTML を生成する想定。プラグインで注入される AdSense ローダー / `VITE_ADSENSE_*` 環境変数分岐は維持される（事前スナップショット A-106 で記録）。

### 鈴木（PO）合意（DAY2 午前）

- 「AdSense 再申請を最優先とした E1 重み 2 倍は妥当。C2 採用に同意」（DAY2 デイリー直後）。

### 渡辺（セキュリティ）事前合意（DAY2 午前）

- C2 は「ビルド時の Node スクリプトで静的 HTML を生成」する方式で、ランタイムの追加攻撃面を増やさず、依存追加もゼロのため OWASP Top 10:2025 観点で本 ADR レイヤーの新規リスクなし。
- `dangerouslySetInnerHTML` 不使用（DoD §10-2）の維持を PoC（TASK-086-4）でも必須化。
- DoD §10 セキュリティ条項は PoC 実装時に再検証する前提で、本 ADR の決定に **事前合意済**。

## 結果（影響）

### PoC スコープ（TASK-086-4 / DAY3）

- 対象 2 ルート: `/`（トップ）+ `/reference/chapter01`
- 静的 HTML 出力: `dist/index.html` を起点に、各ルート相当の `dist/<route>/index.html` を生成。`view-source:` で h1 と本文段落が静的取得できることを必達。
- 実装方針: `scripts/prerender.mjs` を新設し、`vite preview` 上で各ルートの DOM を Node 側で取得（`node-html-parser` または `linkedom` ベースの軽量パース）→ `dist/<route>/index.html` に保存。

### ビルドパイプライン変更

- `package.json` `build` スクリプトに `&& node scripts/prerender.mjs` を追加（PoC 段階では 2 ルートのみ）。
- 既存 `pretest` の `generate-sitemap.mjs` 実行と順序衝突しないことを TASK-086-4 で確認。

### 既存 vitest 影響

- 既存 579+ テスト（特に `Router.seo.test.tsx` 13 / `seo-assets.test.ts` 33 / `sitemap-coverage.test.ts`）への退行ゼロを必須化（TASK-086-5）。
- 新規追加: prerender 出力の HTML スナップショットテスト（h1 / 本文段落 / canonical / OGP / Twitter Card メタ存在検証）を `Router.prerender.test.ts` 等で 1 ファイル追加（TASK-086-5）。

### AdSense ローダー Vite プラグインとの両立

- prerender 出力後の `dist/<route>/index.html` にも AdSense ローダー `<script>` が含まれることを TASK-086-4 で確認（プラグインがビルド出力に対して挿入する設計のため、後処理 prerender でも継承される）。
- `VITE_ADSENSE_*` 環境変数の本番ビルド分岐は維持。

### 404.html フォールバック（PBI-076）との両立

- GitHub Pages の SPA フォールバック `public/404.html` は既存維持。prerender 済みルートは 404 を経由せず直接 `dist/<route>/index.html` が配信される想定。両立は TASK-086-4 で必須検証。

### sitemap.xml / canonical 整合維持

- `routes.ts` 単一ソース基盤（PBI-081）と sitemap.xml 自動生成（`scripts/generate-sitemap.mjs`）は無変更で維持。
- prerender 対象外ルート（DAY3 段階で 2 ルート以外）も既存 SPA 経路で配信されるため、canonical/sitemap 整合は崩れない。

### 次スプリント以降への影響（D-1）

- PBI-087（全ルート展開）は本 ADR 採用案 C2 を前提に着手可能。Sprint025 計画確定。
- PBI-094（ads.txt + 再申請）は PBI-086〜092 完了後（Sprint026 以降）。

### リスク（受容）

- **R-A**: prerender 実行時の `vite preview` ポート競合 → スクリプト内で動的ポート選定（`get-port` 等は使わず Node 標準 `net` で空きポート探索）で対策（TASK-086-4 実装方針）。
- **R-B**: 動的ルート（`/patterns/:id` / `/reference/:chapterId` / `/cases/:id`）の prerender 全件展開時のビルド時間増加 → PoC 段階では 2 ルートのみ、PBI-087 で展開数を段階的に増やす運用で受容。
