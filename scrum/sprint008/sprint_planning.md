## トピック1: Why（スプリントゴール）

### PO（鈴木）からの提案

> Sprint007 で Exam モード（PBI-027）と AI 評価フィードバック（PBI-029）が完成し、Quick → Deep → Exam の 3 段階学習スタイルが画面上で 1 ループ完結した。
> しかし「Exam 完了後の出口」は `alert("時間終了！お疲れ様でした。")` のみで、**学習者が本番タイムマネジメント体験を『結果で振り返り』できない**（Sprint007 P-4）。
> 顧客フィードバック E-1（佐藤①）でも最重要要望として顕在化しており、PBI-030 を **Critical 格上げ**して Sprint008 最優先で着地させる。
> 併せて A-40（PBI-038 ConfirmDialog 内製）/ E-6（PBI-033b 模範解答 21〜30）/ E-5（PBI-036b ツールチップ）/ E-2（PBI-040 キーワードサジェスト）を束ね、Quick → Deep → Exam の 3 段階に「振り返り」フェーズを追加して合格判定の手応えを可視化する。

### スプリントゴール（合意）

> **「Exam 結果画面（正答率・所要時間・A/B/C 別分析）+ ConfirmDialog 内製による 3 ユースケース統一 + キーワードサジェスト拡張で、20 問 90 分の本番タイムマネジメント学習サイクルを『入口から出口まで』完結させ、学習者に『判断の根拠』を示す完全 Exam 体験を実現する」**

### ゴール達成の判定基準

1. Exam 完了時（時間切れ自動終了 / 全 20 問完答）に `ExamResult.tsx` が表示され、正答率（XX/20・%）・所要時間（mm:ss）・A/B/C 優先度別正答数が一画面で確認できる（PBI-030）
2. 「もう一度チャレンジ」「トップへ戻る」導線が機能し、退化動作（PBI-025/026 未実装ブロック非表示）を維持する（PBI-030）
3. `ui/ConfirmDialog.tsx` が新設され、LearningStyle 切替確認 / Exam 中断確認 / 時間切れ警告の 3 ユースケースで `window.confirm` / `alert` から完全置換される（PBI-038）
4. ConfirmDialog はキーボードのみで開閉・確定・キャンセル可能（focus trap・Esc 閉じ・初期フォーカス制御）でライト/ダーク両テーマ AA コントラスト（PBI-038 / DoD §9）
5. cases.json case-021〜030 に modelAnswer + scoringPoints が追加され、計 30 件で模範比較が成立（PBI-033b / E-6）
6. LearningStyleToggle に title 属性 + aria-describedby でツールチップ（Quick=説明重視型 / Deep=じっくり型 / Exam=本番模試）が表示される（PBI-036b / E-5）
7. △判定の各観点に「こんなキーワードがあると◎になります: ○○/××」が 1〜2 個サジェスト表示され、`feedbackKeywords.ts` に △→◎昇格パターン辞書が追加される（PBI-040 / E-2）
8. DoD **21 項目すべて「はい」**を達成（§10 継続適用。ConfirmDialog の DOM 反映は §10-2 / 結果画面の集計純粋関数は §10-1 を機械検証）

### Sprint008 で踏み込まないもの（PO 確認）

- PBI-041（Exam 中断・再開 UX）: A-43 ユーザテスト計画策定が前提のため Sprint009 候補へ繰延。今スプリントは結果画面（出口）整備に集中
- PBI-025 / PBI-026（弱点可視化レーダー / Top3）: PBI-030 退化動作で「該当ブロック非表示」を維持。統合は Sprint009 以降

- PBI-033c（modelAnswer 31〜40）: A-28 消化カレンダーで Sprint009 投入確定
- PBI-039（本格 LLM 連携）: 凍結継続

### 選定理由（議事メモ）

- **PO 鈴木**: Sprint007 P-4「結果画面不在で『振り返り』未完結」が顧客 E-1 で最重要要望として顕在化。PBI-030 を Critical 格上げし Sprint008 最優先で投入。Quick→Deep→Exam の 3 段階に「振り返り」フェーズを追加することで初めて「合格判定の手応え」がプロダクトゴール達成条件 7 として可視化される。
- **Dev 伊藤**: PBI-030 は Exam 集計純粋関数（A/B/C 別正答数集計 / 所要時間 / 正答率）を `domain/examResult.ts` に唯一定義源化（K-9 priorityLabel パターン踏襲）。PBI-038 は `ui/ConfirmDialog.tsx` を共通基盤として整備し、3 ユースケースで `window.confirm` / `alert` を完全置換（Sprint006 P-3 / Sprint007 P-3 の技術的負債解消）。両者ともドメイン層 / UI 層を疎結合に保つ既存パターンで吸収可能。
- **Dev 田中**: PBI-040 は `feedbackKeywords.ts` に △→◎昇格パターンの代表キーワード辞書を追加し、`feedback.ts` 純粋関数で「判定で使われなかった代表キーワード」を選択するロジックを追加。既存 vitest 16 件に境界値 8 件追加で DoD §10-1 を機械検証。PBI-033b / PBI-036b は軽量で既存フレームに沿って吸収可。
- **SM 高橋**: A-45 計画 6〜9pt を 10pt へ拡張する判断は A-26（巻取上限ガイド）/ A-30（沈黙チェック）の 2 スプリント目運用（A-35 / A-36）で吸収可と判定。Day3-4 にバッファを確保しつつ A-38（pr_checklist.md 改訂）/ A-39（役割切替すり合わせ枠）/ A-44（障害物起票判定基準試行）の継続運用で品質ゲートを保つ。

## トピック3: How（タスク分解）

タスク分解の詳細は `sprint_backlog.md` を参照。

### タスク分解の指針（議事メモ）

1. **PBI-030 → ドメイン → UI → 統合**:
   - `domain/examResult.ts` 集計純粋関数（正答率 / A/B/C 別正答数 / 所要時間整形）を vitest 境界値先行（伊藤・田中）
   - `ui/ExamResult.tsx` UI 実装（モバイル幅対応 / ライト・ダーク両テーマ AA / 退化動作）（伊藤）
   - `App.tsx` 統合（time-up → ExamResult 表示・「もう一度」「トップへ戻る」導線）（田中）
   - vitest UI テスト 8 件（中村）
2. **PBI-038 → 共通基盤 → 3 ユースケース置換**:
   - `ui/ConfirmDialog.tsx` 新設（role=dialog / aria-modal / focus trap / Esc 閉じ / 初期フォーカス制御）（伊藤）
   - 3 ユースケース定義（LearningStyle 切替 / Exam 中断 / 時間切れ）（田中）
   - vitest 12 件以上（visible / onConfirm / onCancel / Escape / focus trap / 初期フォーカス）（山本）
   - `App.tsx` の `window.confirm` / `alert` 3 箇所を ConfirmDialog 置換（伊藤）
   - ライト・ダーク両テーマ AA / a11y 確認（田中）
3. **PBI-033b → cases.json 追加**:
   - case-021〜030 に modelAnswer{judgment / reason / action} + scoringPoints[] 追加 + loader.ts スキーマ整合性確認 + A/B/C 30% 分布維持確認（pr_checklist.md §9）（中村・山本）
4. **PBI-036b → ツールチップ**:
   - LearningStyleToggle に title 属性 + aria-describedby 追加（田中）
   - ツールチップ CSS（ライト・ダーク両テーマ AA）+ キーボードフォーカス表示確認（伊藤）
5. **PBI-040 → 辞書拡張 + UI ロジック**:
   - `feedbackKeywords.ts` に △→◎昇格パターン辞書追加（伊藤）
   - `FeedbackView.tsx` に不足キーワード例表示ロジック追加（田中）
   - vitest 境界値 8 件以上追加（中村）
   - キーワード辞書更新ルール（A-42）を `pr_checklist.md` または辞書ファイル冒頭にコメント記載（山本）
6. **DoD §10 継続適用**:
   - §10-1: PBI-030 集計純粋関数 / PBI-040 サジェスト関数の境界値テスト
   - §10-2: PBI-038 ConfirmDialog の DOM 反映で `dangerouslySetInnerHTML` 不使用 / PBI-040 サジェストキーワード表示の XSS 安全（テキストノード描画）を vitest 機械検証
   - §10-3: 本スプリントは適用範囲拡張なし（既存 sessionStorage / localStorage の運用継続）
7. **継続運用アクション**:
   - A-35（巻取上限ガイド 2 回目運用） / A-36（沈黙チェック 2 回目運用 Day2 / Day4） / A-37（priorityLabel 横展開：filterMode / learningStyleLabel の PBI 化 or 技術的負債タスク化判定）
   - A-38（pr_checklist.md「呼び出し側コンテキスト契約レビュー観点」追加） / A-39（Day3 終わりの役割切替すり合わせ 5 分枠） / A-44（障害物起票判定基準ドラフト試行運用）
