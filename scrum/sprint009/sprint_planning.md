## トピック1: Why（スプリントゴール）

### PO（鈴木）からの提案

> Sprint008 で Exam 結果画面（PBI-030）と AI 改善提案（PBI-040）が完成し、Quick → Deep → Exam → 振り返り の学習ループは成立した。
> 一方で主要動線には依然として `window.confirm` 由来の体験差と、Exam 中断時の「破棄しかない」不連続が残っている。
> Sprint009 では **ConfirmDialog の内製化（PBI-038）と Exam 中断・再開 UX（PBI-041）** を中心に、学習を途中で止めても安全に戻れる状態を作る。
> 併せて模範解答骨格 31〜40 件（PBI-033c）を完了し、全 40 件で比較学習を成立させる。余力でラベル定義源の横展開（PBI-042）も片付け、次スプリントのモバイル最適化へ進みやすい土台を整える。

### スプリントゴール（合意）

> **「主要動線のダイアログ体験を統一し、Exam の中断・再開を含めて学習を安全に継続できる状態を完成させる」**

### ゴール達成の判定基準

1. ConfirmDialog が LearningStyle 切替確認 / Exam 中断確認 / 時間切れ確認の 3 ユースケースで統一される（PBI-038）
2. ConfirmDialog は `role="dialog"` / `aria-modal` / focus trap / Esc 閉じる / 初期フォーカスを備え、キーボードのみで完結する（DoD §9-1 / §9-3）
3. Exam 再起動時に「続行 / 新規開始 / キャンセル」の 3 択が表示され、sessionStorage から安全に再開できる（PBI-041）
4. Exam 再開時も Quick / Deep / Exam の履歴集計が汚染されず、§10-3 のスキーマ整合性検証で不正値は安全にフォールバックする（PBI-041）
5. case-031〜040 に modelAnswer + scoringPoints が追加され、全 40 件で模範比較・記述評価が成立する（PBI-033c）
6. filterMode / learningStyle の表示ラベルが唯一定義源に集約され、既存 UI の文字列重複が解消される（PBI-042）
7. ライト / ダーク両テーマ・モバイル幅〜PC 幅で主要画面が破綻しない
8. DoD 21 項目すべて「はい」を達成する

### Sprint009 で踏み込まないもの（PO 確認）

- **PBI-045（モバイルブラウザ利用最適化）**: 重要度は高いが New であり、受入基準の優先画面・確認方法が未確定。Sprint009 中に詳細化し、Sprint010 主軸候補とする
- PBI-025 / PBI-026: ExamResultView への統合は Sprint010 で扱う方針を確認（A-51）
- PBI-043 / PBI-044: Sprint010 以降候補。今回の主軸を散らさないため見送り
- PBI-039: 凍結継続
