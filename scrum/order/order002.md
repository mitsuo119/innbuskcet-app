# 依頼事項メモ order002

## 依頼者

顧客: 佐藤

## 依頼概要

Sprint001 で完成した「インバスケット学習用ローカル稼働Webアプリ MVP」の体験品質を高め、隙間時間で実用的に使える学習ツールへ成長させる。
Sprint002 では UX 強化（操作性・進捗の可視化・コンテンツ拡充）と技術負債の解消を中心に進める。

## 背景・目的

- Sprint001 レビューで顧客（佐藤）から「同僚にも展開したい」「もう少し手応えが欲しい」とのフィードバックがあり、本格的な学習ツール化の機運が高まっている。
- 現状の案件は 28 件まで拡充済みだが、20 パターン（ref 配下の章 08）を網羅的に体験するにはまだ偏りが残る。
- Sprint001 で残った技術負債（vite/esbuild moderate 2 件）を Sprint002 で解消する方針がレトロで合意済み。

## スプリントゴール案（Sprint002）

> 「学習体験の手応えを高める UX 強化（ショートカット・進捗カウンタ・コンテンツ拡充）と、依存更新による技術負債解消を完了させる」

## 受入のイメージ（佐藤目線）

- キーボードのみで A/B/C 回答 → Enter で次の問題、までシームレスに進む。
- 1セッションで「○問中○問正解」がひと目で分かる。
- 同じ案件を「もう一度解く」が押せるので苦手だった案件を反復学習できる。
- `pnpm audit` で High/Critical/moderate ともにクリーン状態に保たれている。

## 確認事項（リファインメント/プランニングで詰める）

1. PBI-011 のキー割当: A/B/C はそれぞれ A/B/C キー、Enter で次の問題、で問題ないか（佐藤と最終合意）。
2. PBI-012 の正答カウンタの粒度: セッション単位でリセットでよいか（永続化はスコープ外）。
3. PBI-013 の追加コンテンツ方針: 既存 28 件を維持しつつ追加するか、入れ替えで質を引き上げるか。
4. PBI-010 の分離方針: ドメイン層を独立パッケージ化するか、フォルダ分割で十分か。
5. PBI-015 の更新範囲: vite/vitest メジャー更新まで踏み込むか、互換マイナー更新に留めるか（バックログ追加要）。
