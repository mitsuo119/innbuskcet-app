# 依頼事項メモ order001

## 依頼者

顧客: 佐藤

## 依頼概要

インバスケット学習用のローカル稼働Webアプリを作成したい。隙間時間で気軽にできるシンプルなものを想定。
（将来的にはiOS/Androidアプリ化も視野。まずはローカル稼働Webアプリでスタート）

## 背景・目的

- インバスケット思考（限られた時間で複数案件の優先順位を判断するスキル）の学習を、隙間時間で繰り返し実施したい。
- 自学自習を支援するため、回答の正誤と「なぜその優先度なのか」の理由提示が必要。

## 機能要件（初期想定）

1. 案件のランダム出題
   - システムが用意した案件（メール/依頼/相談など）から1件をランダムに出題する。
2. 優先度回答
   - ユーザが A（高） / B（中） / C（低） の3択で回答する。
3. 正解と解説の提示
   - 回答後に正解の優先度と、その理由（解説）を表示する。

## 優先度の判断基準

| ランク  | 意味                                        |
| ------- | ------------------------------------------- |
| A（高） | 緊急かつ重要。放置すると大きな損害が出る    |
| B（中） | 重要だが緊急ではない / 緊急だが重要度は低い |
| C（低） | 緊急でも重要でもない。定型的な処理で済む    |

## 非機能・制約

- 稼働環境: まずはローカルで動作するWebアプリ。
- UI: シンプルで隙間時間に使えること（1案件＝短時間で完結）。
- 将来拡張: iOS/Androidアプリ化を見据えた構成が望ましい（必須ではない）。

## スコープ外（現時点）

- ユーザ登録・認証、成績管理、ランキング等のソーシャル機能。
- 案件の自動生成（AI）等の高度な機能。
- モバイルアプリ版の実装。

## スクラムチームへの確認事項（要PO/開発者で詰め）

1. 案件データはどこに持つか（JSON固定 / DB / 後から追加可能にするか）。
2. 案件は何件くらい用意するか（初期セットの規模感）。
3. 1セッションで連続出題するか、1問ごとに完結するか。
4. 技術スタック（フロント/バックの構成、pnpm前提）の選定方針。
5. 「ローカル稼働」の定義（ブラウザのみで完結 / ローカルサーバ起動 など）。

## 受入のイメージ（佐藤目線）

- ブラウザでアプリを開くと、案件が1件表示される。
- A/B/Cを選んで送信すると、正解と理由が表示される。
- 「次の問題」で別案件がランダムに出題される。
- 数分の隙間時間でストレスなく操作できる。
