## トピック1: Why（スプリントゴール）

### PO（鈴木）からの提案

> Sprint005 で記述機能（PBI-023/024）が完成し、合格答案の型を反復できる土台が整った。
> しかし佐藤フィードバックで **「A/B/C 記号だけだと意味が一拍遅れる」「毎問記述はフルだと重い」「Quick/Deep モード切替が欲しい」** という運用面の強い不満が表出。
> Sprint006 は **「学習スタイル（Quick / Deep）の切替を実現し、A/B/C 意味ラベル全画面統一で意味を瞬時に伝える」** ことで、
> 隙間時間と腰を据えた練習の双方で昇進試験合格に効く学習体験へと進化させる。

### スプリントゴール（合意）

> **「学習スタイル（Quick / Deep）切替と記述任意化を導入し、A/B/C 回答の意味ラベル（最優先/中優先/低優先）を全画面で統一表示することで、隙間時間と腰を据えた練習の双方で破綻なく合格答案の型を反復できる学習体験を実現する」**

### ゴール達成の判定基準

1. ヘッダーから [Quick(5分) | Deep(じっくり) | Exam(準備中)] を切替でき、Quick では記述 UI を非表示・Deep では現行 Sprint005 フローを維持する（PBI-036）
2. 学習スタイルは localStorage に永続化され、リロード後も維持される（DoD §10-3 スキーマ整合性検証で吸収）
3. A/B/C 回答が「記号 ＋ 名称（最優先/中優先/低優先）＋ 1 行の意味」でAnswerButtons / ExplanationView / HistoryView / ModelAnswerView の全画面で統一表示される（PBI-035）
4. 履歴・正答率が学習スタイル別（Quick/Deep）に独立集計され、相互に汚染しない（PBI-037）
5. DoD **21 項目**すべて「はい」を達成（§10 はスキーマ整合性検証で localStorage 拡張範囲を再点検）

### Sprint006 で踏み込まないもの（PO 確認）

- PBI-027（時間制限・Exam モード本実装）: PBI-036 で `Exam` セグメントを「準備中」グレイアウトとして枠だけ確保。本実装は **Sprint007 最優先で確定**
- PBI-029（記述自己採点チェックリスト）: 余力枠候補として議論したが、本スプリントは PBI-035/036/037 の 3 PBI 連動の整合性検証を優先し見送り（A-21 継続）
- PBI-025 / 026（弱点可視化）/ PBI-031 / 032（直近10問・ダーク本文）/ PBI-033（modelAnswer 残30件）/ PBI-028（人物・部署ハイライト）: いずれも次回以降の候補

- **PO 鈴木**: 佐藤フィードバックの 3 要望（A/B/C 意味ラベル / 記述任意化 / Quick・Deep 切替）は **互いに密接で分離不能**。PBI-035 単独は「全画面の表示変更」だが PBI-036 と同時投入することで Quick モードでも意味ラベルが伝わる。PBI-037 は PBI-036 で履歴が混ざるリスクを直ちに封じる。**3 PBI 連動の合計 7pt で主軸**を明確にしたい。
- **Dev 伊藤**: PBI-035 の `priorityLabel.ts` 新設は AnswerButtons / ExplanationView / HistoryView / ModelAnswerView の 4 コンポーネント横断リファクタ。先行整備 → 各コンポーネント移行で DRY 化。PBI-036 の `learningStyle.ts` は localStorage 永続化を伴う初の領域で、DoD §10-3（スキーマ整合性検証）を `inbasket.learningStyle.v1` キーに適用。型不整合時は `quick` フォールバック。
- **Dev 田中**: PBI-036 の Quick モードでは `WritingInput` / `WritingPreview` / `ModelAnswerView` を条件分岐で非表示にするが、Deep の現行フローを壊さない設計が要点。`App.tsx` の状態遷移を整理し、純粋関数（モード判定 / フロー分岐）を vitest で先行担保する方針。PBI-037 の HistoryItem 型拡張は PBI-016/020/022 と整合させ、Quick/Deep バッジ（[Q]/[D]）を行内に配置。
- **SM 高橋**: A-22（PBI-027 リファインメント）は完了しSprint007 投入想定。本スプリントは A-20（PBI-033 分割計画）/ A-21（PBI-029 Ready 化）を**リファインメントタスク**として組み込み、Sprint007 投入候補を明確化。A-25（卒業プラクティス culture 反映）は完了済を確認。

## トピック3: How（タスク分解）

タスク分解は `sprint_backlog.md` を参照。

### タスク分解の指針（議事メモ）

1. **PBI-035 → ドメイン先行・横展開**: `domain/priorityLabel.ts` を最初に新設（vitest テスト含む）し、4 コンポーネントへ順次反映。AnswerButtons.tsx は既存リテラルからの参照差し替えで DRY 化を完了させる（伊藤）。
2. **PBI-036 → ドメイン → UI → 結線**: `domain/learningStyle.ts`（型 / localStorage I/O / スキーマ検証）を伊藤が先行整備し、ヘッダーセグメントコントロールを山本、Quick モードでの非表示制御を田中、Deep の「今回は書かない」リンクを田中、モード切替確認ダイアログを伊藤、結線テストを伊藤。
3. **PBI-037 → 型拡張 → 集計拡張 → 表示**: HistoryItem 型に `learningStyle` を追加し（PBI-016/020/022 整合）、`ScoreCounter.tsx` で LearningStyle 別正答率集計を追加、HistoryView 行に小バッジを表示。中村が担当。
4. **DoD §10-3 拡張**: localStorage 永続化対象が `inbasket.learningStyle.v1` 1 キー追加。読み込み時のスキーマ整合性検証＋型不整合時の `quick` フォールバックを `learningStyle.ts` に組み込み、vitest 境界値テストでエビデンス化（伊藤）。
5. **A-16 構造化 handoff（標準運用）**: Sprint005 で卒業済の構造化還流欄を継続運用。Day0 朝に高橋・伊藤で記述（仕様変更 / DoD 強化 / 技術的負債 / プロセス改善 4 トピック）。
6. **リファインメント横断**: A-20（PBI-033 を 1〜2pt 単位に分割）/ A-21（PBI-029 を `scoringPoints[]` 活用 UI 含めて Ready 化）を Day3-4 でリファインメント実施。Sprint007 投入候補を確定。
