## 追加依頼（2026-05-04 佐藤）

### 背景

`cases.json` の `explanation` フィールドに「パターン〇」という記述がある（例: 「重要顧客の重大クレームは緊急度・重要度ともに最高(パターン1)」）。しかし、現状では**ユーザーがそのパターン番号の意味を理解できない**。また、インバスケット試験そのものを学んでいない人にはアプリの価値が伝わりにくいという課題がある。

### 依頼内容

#### 依頼1: パターン別解説ページの追加

インバスケットの**案件パターン（パターン1〜20）を解説するページ**をWebアプリ内に追加してほしい。

- パターンは緊急度×重要度の組み合わせや案件種別で分類される（全20パターン）
- 解説内容は `ref/chapter08-case-patterns.md` に定義された各パターンを参照すること
- パターン一覧画面と、パターン番号をクリック/タップすると表示される詳細画面を用意する
- 詳細画面では以下を表示すること
  - パターン名（例: 「パターン1: 顧客クレーム」）
  - 特徴・典型的な状況
  - 優先度（緊急度・重要度）の判定理由
  - 対応のポイント・回答の骨格
- `explanation` フィールドの「パターン〇」をクリックすると、該当パターンの解説ページに遷移（またはモーダル表示）できると理想的

**受入基準:**

- [ ] パターン1〜20 の一覧が確認できる画面がある
- [ ] 各パターンの詳細（名称・特徴・対応ポイント）が確認できる
- [ ] `explanation` 内の「パターン〇」テキストからパターン解説へアクセスできる
- [ ] スマートフォン（375px幅）でも問題なく表示される

#### 依頼2: インバスケット解説エリアの追加

アプリのメインに、**インバスケット試験そのものの解説コンテンツ**を充実させてほしい。問題回答機能だけでなく、学習・参照に使えるリファレンスブック的なエリアを設ける。

- 解説内容のベースは `ref/chapter01〜12` の内容を参照すること
- 最低限以下のトピックをカバーすること
  - インバスケットとは何か（`ref/chapter01-what-is-inbasket.md` 参照）
  - 評価の考え方・採点基準（`ref/chapter02-scoring-criteria.md` 参照）
  - 優先順位の付け方・緊急度×重要度マトリクス（`ref/chapter05-prioritization.md` 参照）
  - 案件パターン概説（`ref/chapter08-case-patterns.md` 参照）
- 章立て・ナビゲーション構造でコンテンツを整理する
- 既存の問題回答機能と並列でアクセスできるナビゲーション（タブ or メニュー）を用意する

**受入基準:**

- [ ] インバスケットの基本概念が確認できるページがある
- [ ] 優先順位づけの考え方（緊急度×重要度）を解説するページがある
- [ ] パターン一覧解説ページと統合されている（または導線がある）
- [ ] 既存の問題回答画面から解説エリアへ移動できるナビゲーションがある
- [ ] スマートフォン（375px幅）でも問題なく表示される

### Sprint への組み込みについて

- 本依頼は Sprint011 の既存スコープ（PBI-049, PBI-050）とは別件として、Sprint012 以降のリファインメントでPBIに起票してほしい
- PO（鈴木）にて優先順位を判断すること
- 解説コンテンツのソースは `ref/` フォルダの Markdown ファイルを活用することで、実装工数を削減できると考える

## 追加依頼（2026-05-04 佐藤 / Sprint014 向け）

### 背景

Sprint013 で解説リファレンスエリア（PBI-056/057）が公開され、章立てコンテンツが利用可能になった。一方で、エンドユーザ向け Web アプリでは以下の課題が顕在化している。

- 解説本文や見出しに「chapter01」「chapter08」といった**ソースファイル名由来の表記**が残っており、Web 利用者には意味が伝わらず混乱を招く。
- 「（出典: ref/chapter05-prioritization.md）」のような**参照元（ソースパス）表示**は社内資料の体裁であり、一般ユーザ向け UI には不要。
- 解説エリアおよびアプリ全体の**画面デザイン・UX**は機能優先で実装してきたため、視認性・回遊性・モバイル操作性の観点で改善余地がある。

### 依頼内容

#### 依頼1: 解説リファレンスから chapter 表記・参照元表示を削除

- 解説リファレンス画面（および関連コンポーネント）に表示される `chapter01` 〜 `chapter12` 等の**ファイル名由来表記を撤去**する。
- 「出典: ref/...」「参照: chapterXX-...」等の**参照元パス表示**を Web UI 上から削除する。
- 章タイトルは `ref/` のソース名ではなく、利用者が理解できる**自然言語の見出し**（例: 「インバスケットとは」「優先順位の考え方」）のみで構成する。
- 内部のデータ定義（`src/data/referenceData.ts` 等）でソース対応関係をコメントとして残すのは可。ただし UI には出さない。

#### 依頼2: 画面デザインと UX の向上

アプリ全体（問題回答画面・解説リファレンス・パターン解説・法務ページ・ナビゲーション）を対象に、以下の観点で改善する。

- **視認性**: 余白・タイポグラフィ・コントラスト・カード/セクション境界の整理
- **回遊性**: ナビゲーション構造・セクション内リンク・「次の章へ」「一覧へ戻る」等の導線
- **モバイル操作性**: 375px 幅でのタップ領域・スクロール体験・固定要素のはみ出し防止
- **一貫性**: ライト/ダーク両テーマでの色・余白・コンポーネント挙動の統一
- 既存の WCAG AA 準拠（コントラスト・フォーカス可視）を維持・強化

具体的な範囲（ページ/コンポーネント単位の優先）は PO・開発者で分割可能。Sprint014 では**着手しやすい主要画面から段階的に**改善する方針でよい。

### 受入基準

- [ ] 解説リファレンスの UI に `chapter` を含むファイル名由来表記が表示されない
- [ ] 解説リファレンスの UI に `ref/...` 等のソースパスが表示されない
- [ ] 章見出しが利用者向けの自然な日本語タイトルに置き換わっている
- [ ] 主要画面（問題回答／解説リファレンス／パターン解説のいずれか以上）でデザイン・UX の改善が視覚的に確認できる
