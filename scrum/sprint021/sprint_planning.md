## トピック1: なぜこのスプリントは価値があるのか？（Why）

### PO（鈴木）の価値提案

Sprint020 で SEO 技術基盤（History API ルーティング・soft 404 回避・sitemap pathname 化・seo_operations.md 運用）が確立した。order011 で佐藤から提示された方針は **「検索流入の入口を実際に増やすフェーズへ進める」**。残 PBI-077〜081（合計 18pt）の段階消化が直近 3 スプリント方針となる。

Sprint021 では **「コンテンツ拡充 PBI（PBI-079/080）に着手する前に、構造的な品質ゲート（sitemap 自動生成・メタ重複検知）と、クローラ可視性の最終調整（`<a href>` 化）を一式整える」** ことに集中する。

- **PBI-081（sitemap/robots ビルド時自動生成・2pt）を最優先**: Sprint022 以降のコンテンツ重 PBI（PBI-079/080）でルートが増える前に sitemap 更新漏れを構造的に阻止する。CI で不整合検知できる土台を先行投入することで、以後のコンテンツ追加コストを構造的に下げる。
- **PBI-077（`<a href>` 化・3pt）**: Sprint020 で主要画面の href 化は先行済。残る Quick / Deep / Exam スタートの onClick 単独遷移を整理し、修飾キー新規タブ・キーボード操作・a11y の回帰テストで Googlebot のクロール可能性を恒常担保する。
- **PBI-078（canonical/メタ重複網羅レビュー＋自動テスト・3pt）**: コンテンツ拡充 PBI（PBI-079/080）着手前に重複メタ検知の自動テストを敷く。新規ルート追加時にメタ未定義・重複を CI で検出できる構造的ゲートを整備し、レビュー負担を恒常的に下げる。

PBI-079/080（合計 10pt・コンテンツ重）は Sprint022 以降に回し、Sprint021 は **「コンテンツ拡充の前提となる構造ゲート3件を一気に閉じる」** 一点突破で価値を立ち上げる。

### スプリントゴール（合意）

> **検索流入を実コンテンツへ展開する前段として、sitemap/robots 自動生成・内部遷移の `<a href>` 化・canonical/メタ重複自動検知の3つの構造的ゲートを確立し、以降のコンテンツ追加（PBI-079/080）が安全に進む土台を整える**

#### PBI-081 sitemap.xml/robots.txt のビルド時自動生成（2pt）

**受入基準（product_backlog.csv より要旨）:**

- Router 定義を単一ソースとしビルドスクリプトで sitemap.xml を生成する
- sitemap 掲載 URL と実ルートの不整合を検知するテスト（sitemap-coverage.test）を追加し FAIL 時 CI が落ちる
- robots.txt に Sitemap 参照が含まれビルド出力で `__SITE_URL__` が置換される
- ルート追加→自動反映までの手順を seo_metadata_sitemap_guide.md へ反映する
- PBI-076 完了を前提とする
- DoD 21 項目すべて「はい」
