## この章で学ぶこと

- なぜ「自分でやる」が低評価になるのか
- 効果的な委任の公式
- 委任してはいけないケースの見分け方

---

## 「自分でやる」は不合格への道

第1章で述べたとおり、インバスケットは**管理職としての行動**を評価する試験です。管理職の仕事は「部下を通じて成果を出す」ことです。

にもかかわらず、多くの受験者（特にエンジニア）が以下のような回答を書いてしまいます。

```
❌ 「私が直接お客様に連絡します」
❌ 「私がデータを分析して報告書を作成します」
❌ 「私が現場に行って確認します」
```

これらはすべて**「自分でやる」宣言**であり、組織活用力が0点になる回答です。

## 委任の公式

部下や関係者に仕事を任せるときは、以下の**5要素**を必ず含めてください。

```
委任の公式 = Who + What + When + How + Follow-up

Who:    誰に任せるか（具体的な名前・役職）
What:   何をしてもらうか（具体的なタスク）
When:   いつまでに（明確な期限）
How:    どのように（必要に応じて方法・基準を示す）
Follow: 結果をどう報告するか（報告のタイミングと方法）
```

### 悪い委任と良い委任の比較

**悪い委任（丸投げ）**:

```
「田中さん、クレーム対応しておいてください」
```

→ 何をどうすればいいかわからない。期限もない。これは「委任」ではなく「丸投げ」です。

**良い委任**:

```
「田中主任へ
 ・山田商事のクレーム内容を確認し、事実関係を調査してください
 ・本日15時までに調査報告を私宛にメールしてください
 ・顧客へは謝罪と調査中である旨の一報を本日中に入れてください
 ・対応に不明点があれば私に相談してください」
```

→ Who（田中主任）、What（事実確認・顧客一報）、When（本日15時）、How（メール報告）、Follow（不明点は相談）がすべて入っています。

## 「誰に」任せるか ― 委任先の選び方

案件によって、適切な委任先は異なります。

| 委任先                     | 使うケース                     | 注意点                       |
| -------------------------- | ------------------------------ | ---------------------------- |
| **直属の部下**             | 日常業務の範囲内の対応         | スキル・負荷状況を考慮する   |
| **関係部署の担当者**       | 他部署の管轄に関わる案件       | 自部署だけで判断しない       |
| **上司**                   | 自分の権限を超える判断         | 相談ではなく提案の形で上げる |
| **外部（顧客・取引先）**   | 直接のコミュニケーションが必要 | 管理職として自分の名前で連絡 |
| **専門家（法務・人事等）** | 専門知識が必要な案件           | 事実関係を整理してから相談   |

### エンジニア向けのイメージ

```
インバスケットの委任 ≒ タスクのアサインとコードレビューの依頼

・「田中さんに調査を依頼」 → 「田中さんにバグ調査のチケットをアサイン」
・「15時までに報告」 → 「15時までにPRを出して」
・「不明点は相談して」 → 「わからないことはSlackで聞いて」
```

## 組織活用の3パターン

### パターン 1: 下方向の活用（部下への委任）

最も基本的で、最も使用頻度が高いパターンです。

```
「鈴木主任に、品質チェックの手順書を作成してもらう。
 来週月曜日までに素案を作成し、チーム内でレビューした上で
 水曜日の定例会議で最終確認する」
```

### パターン 2: 横方向の活用（他部署との連携）

自部署だけでは解決できない案件で使います。

```
「本件は営業部にも影響があるため、営業部の佐藤課長に状況を共有する。
 合わせて、技術的な見解を品質管理部にも確認し、
 三者で来週前半に対応方針を決定する場を設ける」
```

### パターン 3: 上方向の活用（上司への報告・提案）

権限を超える判断や、経営への影響が大きい案件で使います。

```
❌ 上方向の悪い例:
「本件は部長にご判断いただきたいです」

✅ 上方向の良い例:
「本件は予算規模が大きいため部長への報告が必要と判断します。
 私の意見としては案Aを推奨します。理由は[根拠]。
 部長に本日中に概要を報告し、ご判断を仰ぎます」
```

**重要**: 上司に持っていく場合でも、**自分の意見・推奨案を添える**ことで意思決定力の評価を維持できます。「わかりません、決めてください」は最悪のパターンです。

## 委任してはいけないケース

以下のケースは、管理職自身が対応すべきです。

| ケース                                                 | 理由                           |
| ------------------------------------------------------ | ------------------------------ |
| **部下の人事に関する相談**（退職、異動、ハラスメント） | 管理職としての直接対応が必要   |
| **重要顧客への最終回答**                               | 管理職の名前で責任を持って回答 |
| **部門の方針決定**                                     | 管理職が決めるべきこと         |
| **コンプライアンス違反への対処**                       | 管理職への報告義務がある事案   |

ただし、これらでも**情報収集や準備作業は部下に委任**できます。

```
「本件は私が直接対応しますが、
 田中さんに事前に関連データをまとめてもらいます。
 本日14時までに過去の取引履歴と顧客情報を整理してください」
```

## 委任の量を意識する

合格ラインの目安として、全案件のうち：

| 対応方法                         | 目安の割合 |
| -------------------------------- | ---------- |
| 部下に委任して自分は方針だけ示す | 40〜50%    |
| 自分が主導し部下がサポート       | 20〜30%    |
| 関係部署と連携して対応           | 15〜20%    |
| 自分が直接対応する               | 10%以下    |

**自分が直接対応する案件は全体の1割以下**に抑えるのが目安です。

:::message
**この章のまとめ**: 管理職は「自分で成果を出す」のではなく「部下を通じて成果を出す」。委任は5要素（Who/What/When/How/Follow-up）を必ず含める。丸投げでも自分でやるでもなく、「方針は自分で示し、実行は任せ、フォローする」のが高評価の委任です。
:::
